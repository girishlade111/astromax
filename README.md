# Astromax

A bold, editorial one-page portfolio and agency site built with **Astro 7** and **Tailwind CSS v4**. Astromax pairs a monochrome grid-based layout with sharp typography, a marquee banner, a filterable work gallery, service and testimonial sections, and a full SEO/social metadata setup.

The design language is intentionally stark: near-black canvas, warm off-white text, a single orange accent, uppercase display type, and hairline borders that divide every section.

## Features

- **Astro 7 static output** — ships zero JavaScript by default; fast HTML-first pages.
- **Tailwind CSS v4** via the official `@tailwindcss/vite` plugin. No `tailwind.config.js` — the theme lives in CSS using the `@theme` directive.
- **Typed image pipeline** — work thumbnails are imported from `src/images/` and rendered with `astro:assets` `<Image />`, giving automatic optimization, hashed filenames, and width/height to prevent layout shift.
- **Keen Slider carousel** for the work gallery, loaded from CDN.
- **Alpine.js** for small, declarative interactions (loaded from CDN).
- **Sitemap integration** (`@astrojs/sitemap`) generated at build time.
- **SEO component** (`@lexingtonthemes/seo`) with canonical URL, Open Graph, Twitter cards, and JSON-LD `WebSite` structured data.
- **Accessibility touches** — marquee content mirrored into an `sr-only` block, semantic `section`/`figure`/`blockquote` markup, and focus-visible styles.
- **Utility-first styling with `@/` path alias** mapped to `src/`.
- **`compressHTML: true`** in the Astro config for smaller payloads.

## Getting started

1. **Clone the repository**

   ```bash
   git clone https://github.com/girishlade111/astromax.git
   cd astromax
   ```

2. **Install dependencies**

   ```bash
   npm install
   ```

3. **Start the dev server**

   ```bash
   npm run dev
   ```

4. **Open the site** at <http://localhost:4321>.

5. **Verify a production build** before deploying:

   ```bash
   npm run build
   npm run preview
   ```

`dist/` is generated by the build and is ignored by Git. `node_modules/` is also ignored.

## How the page is assembled

`src/pages/index.astro` is the only route. It wraps the landing sections in `BaseLayout`:

```astro
<BaseLayout>
  <Hero />        <!-- headline + grid background + marquee + testimonials -->
  <Work />        <!-- filterable image slider of themes/projects -->
  <Intro />       <!-- large statement copy -->
  <Services />    <!-- four-column service list from a local array -->
  <Cta />         <!-- full-width orange call-to-action -->
</BaseLayout>
```

`BaseLayout.astro` renders the document shell, adds the horizontal rail borders (`border-x border-white/20`), and slots `Navigation` and `Footer` around the page content.

`BaseHead.astro` is the single place for everything in `<head>`:

- imports `src/styles/global.css`
- renders `AstroSeo` (title, description, canonical, Open Graph, Twitter)
- emits JSON-LD `WebSite` structured data
- favicon and web manifest links (`/favicons/*`)
- Google Fonts: **Geist** and **Geist Mono**
- CDN assets: Alpine.js and Keen Slider CSS

## Customizing the template

### Design tokens & theme

Tailwind v4 is configured entirely in `src/styles/global.css`. Colors, fonts, gradients, and animations are CSS variables inside `@theme`:

```css
@import "tailwindcss";

@theme {
  --font-sans: Geist, sans-serif;
  --font-mono: Geist mono, monospace;

  --color-black: #1e1e1e;
  --color-white: #e7e7d8;
  --color-eagle: #afac95;
  --color-orange: #ea4125;

  --background-image-grid: /* repeating linear gradients */;
  --animate-marquee: marquee 50s linear infinite;

  @keyframes marquee {
    0%   { transform: translateX(0%); }
    100% { transform: translateX(-100%); }
  }
}
```

Because these are theme tokens, you use them as normal utilities: `bg-black`, `text-white`, `text-eagle`, `bg-orange`, `bg-grid`, `animate-marquee`. To rebrand, change the hex values here — every section updates at once.

Plugins are declared in the same file with `@plugin`, for example:

```css
@plugin "@tailwindcss/typography";
@plugin "@tailwindcss/forms";
```

### Site metadata & SEO

Edit `src/components/BaseHead.astro`:

- `AstroSeo` props: `title`, `description`, `canonical`, `openGraph`, `twitter`
- the `structuredData` object (site name, URL, description)
- `<meta name="author">` and favicon paths

Edit `astro.config.mjs` and set `site` to your production domain. The sitemap integration uses this value to generate absolute URLs:

```js
export default defineConfig({
  site: "https://your-domain.com",
  compressHTML: true,
  integrations: [sitemap()],
  vite: { plugins: [tailwindcss()] },
});
```

### Content

All copy is local to its component — there is no CMS and no content collection:

| Section | File | What to edit |
| :--- | :--- | :--- |
| Hero headline | `src/components/landing/Hero.astro` | the `<h1>` text |
| Marquee messages | `src/components/landing/Banner.astro` | the `messages` array |
| Testimonials | `src/components/landing/Testimonials.astro` | the `testimonials` array (`text`, `author`, `title`) |
| Work gallery | `src/components/landing/Work.astro` | the `themes` array and image imports |
| Intro statement | `src/components/landing/Intro.astro` | heading and paragraph |
| Services | `src/components/landing/Services.astro` | the `services` array (`title`, `description`) |
| CTA | `src/components/landing/Cta.astro` | label and link |
| Navigation / Footer | `src/components/global/*` | links and legal copy |

### Images

Portfolio thumbnails live in `src/images/work/`. They are imported at the top of `Work.astro` and rendered with Astro's image component, so the optimizer handles resizing and format conversion at build time:

```astro
---
import { Image } from "astro:assets";
import Trendspotter from "@/images/work/trendspotter.png";
---

<Image src={Trendspotter} alt="Trendspotter" />
```

To add a project: drop the image in `src/images/work/`, import it, and append an entry to the `themes` array.

Static, unprocessed assets (favicons, robots.txt, PDFs) belong in a `public/` directory at the project root. Astro copies that folder to `dist/` unchanged and serves it from `/`.

## Deployment

The build output is fully static. Any static host works.

**Netlify**

```bash
npm run build
# publish directory: dist
```

**Vercel** — framework preset *Astro*; build command `npm run build`, output `dist`.

**Cloudflare Pages** — build command `npm run build`, build output directory `dist`.

**GitHub Pages** — already configured. The workflow at `.github/workflows/deploy.yml` builds on every push to `main` and publishes `dist/` via GitHub Actions.

- `astro.config.mjs` sets `site: 'https://girishlade111.github.io'` and `base: '/astromax'` for the project-page subpath.
- Internal links must respect the base path. Use `import.meta.env.BASE_URL` for files in `public/`:

  ```astro
  ---
  const base = import.meta.env.BASE_URL.replace(/\/$/, "") + "/";
  ---
  <link rel="icon" href={`${base}favicons/favicon-32x32.png`} />
  ```

- Repository settings must keep **Settings → Pages → Build and deployment → Source** set to **GitHub Actions**.
- If you rename the repository or move to a custom domain, update `site` and `base` to match.

**Any static server**

```bash
npm run build
npx serve dist
```
